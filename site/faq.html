常见问题

安装前，你大概想知道这些

按决策顺序排列：依赖 → 数据库 → 部署限制 → 运维与边界。

我需要先装好媒体服务器、下载器和刮削工具吗？

不需要。它默认用 SQLite 单独就能跑，先用来检索、浏览、整理元数据。

要跑通“下载 → 整理 → 入库”闭环，再接入一个下载器、一个整理工具和一个媒体服务器 —— 这三者可以是你已经装好的，也可以让全栈 Compose 一起装；跑在别的机器上就填接入地址。

支持哪些数据库？

默认 SQLite：零配置、单文件，几十万条以内够用。

生产建议 PostgreSQL，Compose 里可选启用（--profile with-db）。 媒体文件始终留在你自己的存储上，不会被搬进数据库目录。

为什么首次部署必须走完引导向导？

未完成向导前其它页面一律不开放，这是刻意的：半配置状态（鉴权没设、服务地址空着） 直接暴露在网络上，正是要避免的事。

它同时也是一次配置自检 —— 走完，链路需要的东西就都到位了。

数据和缓存存在哪里？删掉会怎样？

容器内 /app/data 必须持久化挂载：运行配置、封面缓存、 SQLite 回退库都在里面。

删掉它等于把缓存好的封面和元数据重抓一遍，可能是数 GB 流量和很长等待。 媒体文件不在这个目录里，不会动到你的片库。

封面缓存能清理吗？

能，但代价明确：清掉后每次打开详情都要回源，而回源一条可能要几十秒，翻页会明显变慢。

建议把它纳入备份 —— 它属于“看着像临时文件、其实很值钱”的那一类。

支持 ARM / Apple Silicon 吗？

官方镜像目前只构建 linux/amd64。

  • ARM（部分 ARM NAS、Apple Silicon）需自行从源码构建镜像；
  • x86 模拟可以跑，但性能损失明显，不建议长期使用；
  • 构建配置在仓库里，加一行多架构参数即可产出 ARM 镜像，欢迎提 PR。
端口冲突怎么办？

所有对外端口都在 .env 里可改，Compose 与镜像里没有写死。

应用默认对外 8012（容器内 8000）；全栈形态下每个服务端口 都能单独指定。用仓库里的 agent 提示词安装时，它会先探测端口占用， 再把建议端口列给你确认。

库里的密钥是明文存储的吗？

支持加密存储：敏感配置（API Key、口令、令牌）写入时用 AES-256-GCM 加密，密钥来自你设置的环境变量。

一个容易误解的点：加密只发生在写入那一刻。先明文存进去、后补密钥， 已有记录不会被自动加密 —— 所以启动时会点名仍是明文的敏感键， 看到提示重新保存一次即可。

怎么升级？出问题怎么回滚？

镜像按版本标签发布，升级就是换标签重建容器。数据在挂载卷里，与镜像版本无关：

  • 升级：拉取新标签，重建容器；
  • 回滚：标签改回上一版，重建容器；
  • 建议用具体版本号而不是 latest，并保留上一版镜像 —— 回滚的前提是它还在。
翻译功能必须装本地大模型吗？

不必需。翻译是可选能力：不配就不翻，其它功能照常。

要启用，需要一个兼容 OpenAI 接口的推理服务（Ollama 等），模型自己选。 走本地而非云端，因为量级大且文本不适合外发。

它能支撑多大的库？

设计目标是十万条起步、六位数以上的库。

靠两件事成立：元数据与封面落库缓存，日常浏览不回源；列表页与详情页分开取数， 不为一条详情拖慢整页。规模再上建议切 PostgreSQL。

它和别的媒体库自动化工具会冲突吗？

功能定位有重叠，不建议对同一个下载器实例同时做同一类调度 —— 两个调度器改同一个任务的状态，很容易互相打架。

确实并存时，请按标签把任务区分开。BusTerminal 用独立标签标记自己的任务。
