01 / 现状

你的媒体库，是被五个工具
和一堆脚本粘起来的

找片在一个地方，下载在另一个地方，改名靠手，入库靠猜。哪一步断了，没有人告诉你 —— 直到你想看的时候，才发现它根本不在库里。

往下滚，看它们被收成一条线。

找片 · 站点 A 下载 · qBittorrent 改名 · 手工 + 脚本 刮削 · 工具 B 播放 · Jellyfin 状态 · 没人记 BusTerminal 来记账

02 / 链路

一条链路，八段状态

每一段都记录谁发起、进行到哪、成功还是失败。哪一环断了，一眼看得出来。

  1. 内容发现等待完成
  2. 元数据缓存等待完成
  3. 磁链选择等待完成
  4. 下载执行等待完成
  5. 文件投放等待完成
  6. 媒体库入库等待完成
  7. 状态回写等待完成
  8. 订阅 / 清理等待完成
闭环每一段都有回执
它不碰你的文件。只记录状态、下发指令、校验结果 —— 下载和整理仍交给你已经信任的工具。

05 / 边界

不替代你已经在用的工具

每个环节交给最合适的组件，它只负责决策、下发与记账。

qBittorrent下载执行 刮削工具命名、整理、生成 NFO Jellyfin媒体库扫描与播放
BusTerminal发现、决策、状态与重试 不碰你的文件 · 只记状态、下发指令、校验结果
组件之间不用你写脚本粘合 —— 链路、状态回写、失败重试都由它驱动，接入地址填一次即可。

04 / 怎么跑

三种起手式，挑一个

官方镜像已发布在 GHCR，不用 clone 源码，也不用自己构建。

terminal

默认 SQLite，不需要额外容器。开 8012 端口就进引导向导。

docker run -d \
  --name bus_terminal \
  -p 8012:8000 \
  -v "$PWD/busterminal-data:/app/data" \
  ghcr.io/seldoms/busterminal:latest

路径与端口全部可配，可选带上 PostgreSQL。适合长期运行。

git clone https://github.com/seldoms/BusTerminal.git
cd BusTerminal
cp .env.install.example .env
vi .env   # port & db password
docker compose -f docker-compose.install.yml up -d

连数据库、下载器、刮削工具、媒体服务器一起装。每个服务挂一个 profile，装哪些由你决定。

cp .env.fullstack.example .env
COMPOSE_PROFILES=db,qb,amane,jellyfin \
  docker compose -f docker-compose.fullstack.yml up -d
不想自己排端口和路径？ 把 docs/AGENT_FULLSTACK_INSTALL.md 整段交给你的 AI agent：它先探查本机， 把服务清单摊给你逐项选，你确认之后才动手安装。已经装好的服务只复用、不重装。
