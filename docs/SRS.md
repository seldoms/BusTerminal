## 1. 引言与架构设计原则

本文档从现代软件工程（Software Engineering）与领域驱动设计（Domain-Driven Design, DDD）视角出发，重新划定 BusTerminal 系统的业务模块边界与职责架构。

### 1.1 设计原则
1. **高内聚，低耦合 (High Cohesion, Low Coupling)**：每个模块专注于单一业务领域，禁止跨领域直接穿透修改数据库。
2. **单一职责原则 (Single Responsibility Principle, SRP)**：各模块只负责特定的业务逻辑或外部系统适配。
3. **隐式依赖转显式契约 (Explicit Contracts & Interfaces)**：服务间通过定义明确的 DTO (Data Transfer Object) 与 Service API / 事件总线通讯。
4. **防腐层 (Anti-Corruption Layer, ACL)**：对外部抓取源（JavBus、Jable 等）、下载客户端（qBittorrent）和媒体服务器（Jellyfin）均设立适配器隔离防腐层，外部接口变更不影响核心业务逻辑。
5. **业务操作与配置中心彻底解耦 (Operational Views vs. Setting Hub Decoupling)**：业务功能 API 与页面仅消费持久化的配置状态，禁止在业务组件内交织配置写入逻辑。所有配置写操作收拢至统一配置服务。

### 3. 各模块详细功能规格说明

#### 模块 1：外部数据源抓取适配器服务 (Provider Scraping Adapter Service)
* **定位**：负责所有外部数据源（JavBus、Jable、JavDB、AirAV 等）的协议通讯、反爬绕过与 HTML 解析。
* **核心职责**：
  * 对外暴露标准化的 REST/RPC 接口，返回统一格式的影片、演员及分类 DTO。
  * 内置域名轮询机制（Domain Rotation）与健康度监测，自动屏蔽失效域名。
  * 实现渐进式降级抓取：快速 HTTP 抓取 ➜ 无头浏览器（Scrapling）防封锁抓取。
* **边界约束**：**绝对无状态**，不直接读写本地数据库，不关心影片是否已被下载。

#### 模块 2：影视知识库与元数据存储服务 (Media Metadata & Repository Service)
* **定位**：系统的数据内核，管理影片、演员、关联关系及本地媒体缓存。
* **核心职责**：
  * 负责实体数据库（PostgreSQL 关系型数据库）的 CRUD 映射、复杂关联索引优化与高并发事务维护。
  * 提供统一番号归一化引擎（Canonical ID Normalizer），消除不同站点番号格式差异。
  * 独立提供代理图片与封面存储（Image Cache Subsystem），支持动态阈值与 LRU 自动清理。
* **边界约束**：仅管理领域元数据资产，不发起外部主动爬取，不直接触发下载命令。

#### 模块 3：订阅管理与追更调度引擎 (Subscription & Orchestration Service)
* **定位**：用户的增量追踪控制大脑。
* **核心职责**：
  * 管理用户的订阅策略（演员关注、关键词订阅、标签订阅）。
  * 维护订阅刷新调度周期，将“虚拟/内部订阅 URL”解析并转换为真实来源数据抓取命令。
  * 负责扫描增量内容并生成待处理“候选下载事件”（Pending Intent），推送至决策模块。
* **边界约束**：不直接向下载器提交任务，仅负责识别“发现新影片”。

#### 模块 4：磁链智能决策与品质评估引擎 (Magnet Intelligence & Selection Engine)
* **功定位**：负责针对候选影片的目标磁链提取、品质打分与最优目标决策。
* **核心职责**：
  * 从抓取到的磁链列表中提取元数据（清晰度、字幕标签、文件大小、做种数）。
  * 根据用户配置的权值（如：1080P/4K + 中文字幕 > 高码率 > 体积）计算打分并选择最优磁链。
  * 负责磁链级别的幂等去重校验，处理无磁链影片的休眠重试队列。
* **边界约束**：不直接调用下载器 API，仅输出包含最佳磁链与目标的“下载任务准备包”。

#### 模块 5：下载客户端适配与调度服务 (Download Client Adapter & Scheduler)
* **定位**：下载器（qBittorrent / Aria2 等）的防腐适配器与下载调度引擎。
* **核心职责**：
  * 提供统一的 `IDownloadClient` 接口，屏闭不同下载器 API 差异。
  * 监控任务进度、下载/上传速度、做种时间与比例。
  * 提供资源与风险熔断：磁盘空间低水位预警（Disk Threshold Guard）、JAV 垃圾广告小文件自动屏蔽与删除。
  * 当客户端离线时，维护本地持久化任务队列（`waiting_external_service`）。
* **边界约束**：仅负责文件下载阶段的管理，不参与下载完成后的整理重命名。

#### 模块 6：资产整理与入库流水线服务 (Asset Organizer & Ingestion Pipeline)
* **定位**：文件生命周期的加工流水线。
* **核心职责**：
  * 监听下载完成事件，校验下载文件完整性与安全合规性。
  * 执行清洗规则：清除无用样品片段、广告链接、说明文档。
  * 依规则将最终影视文件平移或硬链接（Hardlink）投放至指定的 Staging 或媒体库目录，并生成刮削 NFO。
  * 触发通知给媒体服务器模块。
* **边界约束**：只进行受控目录内的文件整理，不越权删除外部非受控目录。

#### 7. 媒体服务器集成与同步服务 (Media Server Adapter & Sync Service)
* **定位**：对接媒体服务器（Jellyfin / Emby / Plex）的桥梁。
* **核心职责**：
  * 提供统一的 `IMediaServer` 接口，触发媒体库扫描、刷新元数据。
  * 双向同步用户的播放状态（`is_watched`）、播放次数（`watch_count`）、点赞收藏（`is_liked`）。
  * 接收 Webhook 事件实时响应用户播放动作。
  * 执行受控的媒体项删除（Delete Item）。
* **边界约束**：删除操作受严格的确认与二次校验锁保护。

#### 模块 8：用户行为分析与推荐引擎 (Behavioral Analytics & AI Engine)
* **定位**：基于数据的智能决策层。
* **核心职责**：
  * 聚合 Jellyfin 播放数据，计算用户观影偏好（如最爱女优排行榜、看完未收藏率）。
  * 生成“自动化行动候选”（Automation Candidate），如：自动关注高频观看的女优、自动推送同类型影片。
  * 支持三种控制模式：`Off`（关闭）、`Suggest`（生成推荐候选待人工审批）、`Auto Approve`（低风险自动执行）。
* **边界约束**：不直接篡改数据库或盲目下载，所有建议必须包含推理依据树（Reason Tree）。

#### 模块 9：片源生命周期与存储防爆管理服务 (Lifecycle & Retention Governance Service)
* **定位**：媒体资产的全生命周期追踪与磁盘防爆淘汰中心。
* **核心职责**：
  * 维护影片在系统中的 6 维生命周期状态（Discovery ➜ Decision ➜ Download ➜ Organize ➜ Jellyfin ➜ Cleanup）。
  * 执行冷门/已看片源淘汰规则：筛选 `is_watched` + `watch_count <= 1` + `not is_liked` 的目标。
  * **执行物理与数字三联删除**：同时清除 Jellyfin 条目 + 本地物理文件 + qBittorrent 下载任务。
  * **防重复下载凭证锁**：**持久保留数据库元数据记录**，确保后续订阅更新时自动过滤已删片源。
* **边界约束**：删除操作具备幂等性和日志审计。

#### 模块 10：平台基础设施与系统总控服务 (Platform Infrastructure & Control Console)
* **定位**：系统的底座与控制台。
* **核心职责**：
  * 统一配置中心（System Config Service）：收拢环境变量、数据库配置与用户界面设置。
  * 统一任务注册表（Task Registry）：管理所有后台 Worker 运行状态、连续失败次数与运行日志。
  * 提供 RESTful API 路由装配与 WebSocket 状态推送。
  * 托管 Web UI 静态资产。
* **边界约束**：只做路由分发与基础设施支撑，不包含具体领域业务逻辑。

## 4. 模块间交互契约与事件驱动架构

为确保低耦合，系统推荐基于**内存事件总线 (Event Bus)** 进行异步通信：

```text
[内容发现/订阅]  ──> (Event: MovieDiscovered) ──> [磁链选择模块]
[磁链选择模块]    ──> (Event: TorrentSelected)  ──> [下载管理模块]
[下载管理模块]    ──> (Event: DownloadCompleted)──> [资产整理模块]
[资产整理模块]    ──> (Event: MediaIngested)    ──> [媒体服务器模块]
[媒体服务器模块]  ──> (Event: MovieWatched)     ──> [行为分析/生命周期模块]
[生命周期模块]    ──> (Event: SpaceEmergency)   ──> [空间治理模块]
```

## 5. 非功能性需求规格

1. **接口延迟与并发**：知识库与缓存模块必须在 50ms 内响应元数据查询；网络爬虫支持异步并发与超时自动退避。
2. **容灾与自愈能力**：外部服务（qB/Jellyfin/爬虫目标站）故障或离线时，系统任务状态进入挂起队列，服务恢复后自动恢复。
3. **数据一致性**：删除片源时，物理文件删除与数据库凭证锁写入必须满足事务原子性（或补偿事务）。
